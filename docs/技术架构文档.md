## 技术架构文档

### 1. 系统总体架构设计

### 3. 模块划分与职责

#### 3.1 静态分析模块（static_analysis）

- **APKAnalyzer**：单个APK文件分析
  - 提取APK权限信息
  - 分析权限风险等级
  - 生成静态分析报告

- **APKBatchAnalyzer**：批量APK分析
  - 遍历目录中的APK文件
  - 调用APKAnalyzer进行分析
  - 汇总分析结果

#### 3.2 动态分析模块（dynamic_analysis）

- **DynamicAnalyzer**：单个应用动态分析
  - 安装和启动应用
  - 监控敏感API调用
  - 分析网络流量
  - 检测隐私数据泄露
  - 生成动态分析报告

- **DynamicBatchAnalyzer**：批量应用动态分析
  - 遍历目录中的APK文件
  - 调用DynamicAnalyzer进行分析
  - 汇总分析结果

#### 3.3 动态引擎模块（dynamic_engine）

- **FridaAnalyzer**：Frida动态分析
  - 注入应用进程
  - 监控敏感API调用
  - 收集分析数据

- **HookManager**：Hook管理
  - 管理Hook脚本
  - 处理Hook事件
  - 确保Hook稳定性

#### 3.4 综合分析模块（integrated_analysis）

- **IntegratedAnalyzer**：综合分析
  - 整合静态和动态分析结果
  - 计算风险评分
  - 判定风险等级
  - 生成综合分析报告

#### 3.5 Web Dashboard模块（web_dashboard）

- **Flask应用**：Web服务器
  - 提供Web界面
  - 处理用户请求
  - 展示分析结果

- **前端界面**：
  - 上传APK文件
  - 显示分析进度
  - 展示分析结果
  - 提供报告下载

### 4. 接口设计规范

#### 4.1 内部接口

- **静态分析接口**：
  - `APKAnalyzer.analyze(apk_path)`：分析单个APK文件
  - `APKBatchAnalyzer.analyze_all()`：批量分析APK文件

- **动态分析接口**：
  - `DynamicAnalyzer.analyze(apk_path)`：动态分析单个应用
  - `DynamicBatchAnalyzer.analyze_all()`：批量动态分析应用

- **综合分析接口**：
  - `IntegratedAnalyzer.calculate_risk_score(static_result, dynamic_result)`：计算风险评分
  - `IntegratedAnalyzer.generate_integrated_report(static_results, dynamic_results)`：生成综合报告

#### 4.2 外部接口

- **Web API**：
  - `POST /api/analyze`：上传APK文件并分析
  - `GET /api/report/{apk_name}`：获取分析报告
  - `GET /api/summary`：获取分析汇总信息

- **命令行接口**：
  - `python integrated_analysis.py`：运行完整分析
  - `python check_apk.py <apk_path>`：分析单个APK

### 5. 数据存储方案

- **分析结果存储**：
  - 静态分析结果：`results/{apk_name}_analysis.json`
  - 动态分析结果：`results/{apk_name}_dynamic_analysis.json`
  - Frida分析结果：`results/{apk_name}_frida_hook.json`
  - 综合分析报告：`results/integrated_analysis_report.json`

- **配置数据存储**：
  - 应用类型和权限配置：`app_type_permissions.py`
  - 分析规则配置：通过代码中的常量定义

- **日志存储**：
  - 分析过程日志：`app_privacy_detector.log`

### 6. 安全架构

- **分析环境隔离**：
  - 动态分析在Android设备或模拟器中进行
  - 分析过程不影响宿主系统

- **数据安全**：
  - 分析结果本地存储，不上传到远程服务器
  - 敏感信息处理符合隐私保护要求

- **权限控制**：
  - Web界面访问控制（可选）
  - 分析过程中的权限管理

### 7. 部署架构

- **本地部署**：
  - 安装Python环境和依赖包
  - 安装ADB和Frida工具
  - 配置Android设备或模拟器
  - 运行分析脚本

- **Web部署**：
  - 启动Flask Web服务器
  - 配置静态文件路径
  - 访问Web界面进行操作

### 8. 扩展性设计

- **应用类型扩展**：
  - 在`APP_TYPES`字典中添加新的应用类型
  - 在`NECESSARY_INFO`字典中定义新应用类型的必要权限

- **分析规则扩展**：
  - 扩展权限风险等级映射
  - 添加新的敏感API监控规则

- **集成扩展**：
  - 提供API接口与其他工具集成
  - 支持自定义分析插件

### 9. 技术风险评估与应对策略

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| Frida连接失败 | 动态分析无法进行 | 提供多种连接策略，包括PID附加和spawn方式 |
| ADB设备连接问题 | 无法进行动态分析 | 增加设备连接检测和自动重连机制 |
| 应用启动失败 | 动态分析无法完成 | 提供应用启动状态检测，支持多种启动方式 |
| 分析时间过长 | 影响用户体验 | 优化分析算法，增加并行处理能力 |
| 内存占用过高 | 系统性能下降 | 优化内存使用，采用流式处理大型数据 |
| 权限识别不准确 | 分析结果偏差 | 定期更新权限数据库，提高识别准确率 |
